# Execution capture spike

Run from the workspace root:

```sh
/tmp/opencode/llmcmd-dotnet11/dotnet build spikes/ExecutionCapture/ExecutionCapture.csproj
/tmp/opencode/llmcmd-dotnet11/dotnet run --no-build --project spikes/ExecutionCapture/ExecutionCapture.csproj
```

The executable runs a no-credentials example against an actual Microsoft.Extensions.AI 10.11.0 pipeline and fake client. It writes `/tmp/opencode/llmcmd-runtime/sample-record.json`. TUnit contract tests live in `tests/LlmCmd.Tests`; see its README for the test command and report. It targets .NET 11 with C# 15, tested with SDK 11.0.100-rc.3.26522.148. `DemoCommand` is hand-written; this runtime and the separate `TypedCommands` generator spike are not integrated.

The optional explicit command ID wins over its fully qualified type name. A rename or namespace move changes the default ID. Hashes identify UTF-8 raw definition and effective *templates* only; they do not cover parameters or settings and are not secret-safe identifiers. Runtime replacement of caller parameters is disabled by default and requires an explicit per-parameter opt-in. Captured origins distinguish caller and runtime values. Parameter replacement is validated as a batch. The runtime snapshot is obtained once per call; the fake is Redis-equivalent in role, not an implementation of Redis, atomic revision semantics, caching, or failure policy. The brace parser supports the demonstrated grammar only. Substituted values are never parsed again.

Settings merge per field from platform, command, snapshot, and call, and produce a new MEAI `ChatOptions` per call. Provider selector and model ID are distinct. The builder configuration is injected once per provider; the observer is registered last, closest to the provider. Its AsyncLocal context is restored in finally. The test places retry and request mutation outside that observer, proving two attempts and actual near-provider text/options. Provider factories and built pipelines belong to the executor and are disposed by it. Each provider attempt holds a cloned usage snapshot and actual response model; fake flat rates apply equally to all models. Cost sums observed attempts once. Usage and fake costs are illustrative only; unsupported categories, absent usage, and failed attempts with unknown usage yield unknown total cost. A lack of an observed attempt does not establish a cache hit.

Capture records include schema version, execution ID, optional trace/span IDs when an activity exists, start time, execution duration excluding collector time, and separate original and effective templates and parameter snapshots. Parameter and attempt collections are read-only snapshots. The activity and counter expose only a bounded outcome tag; sensitive text and caller details are captured by the collector. Snapshot, provider, and collector failures are demonstrated separately from a successful model response. The collector gets an independent timeout token to try to capture cancelled calls. WaitAsync bounds asynchronous waits even when a collector ignores cancellation; a synchronous blocking collector invocation or cancellation callback cannot be bounded by this mechanism. Timed-out work may continue in the background. A bounded queue is a production gate. Execution is classified before one finalization pass. Enrichment exceptions produce unknown cost and a warning without losing the response. Caller-token cancellation is distinct from a live-token OperationCanceledException, which is recorded as a possible provider/source timeout or internal cancellation. Validation failures produce a collected invalid execution and a bounded outcome metric without a model call. Exception messages, raw prompts, parameters and caller paths may be sensitive; the collector needs explicit access, retention and redaction policies before deployment. Capture hashes are not suitable for anonymization.

Streaming, tool-loop retries, multiple messages and multimodal content, all MEAI settings, actual cache semantics, durable collection, provider disposal on partial constructor failure, cross-process propagation, and generator integration are production gates. The example cost calculation has no real rates or currency. Top-level response token counts describe only the final response, not total billing. Per-attempt usage is authoritative for accounting. The prototype snapshots all current MEAI usage counters and additional counts per attempt, but supports pricing only aggregate input/output token counts; richer usage needs an explicit accounting model. The result uses a C# 15 native `closed record` hierarchy with an exhaustive `Match` switch. The build treats non-exhaustive switch warnings as errors. Nullable references require explicit handling at external boundaries.
