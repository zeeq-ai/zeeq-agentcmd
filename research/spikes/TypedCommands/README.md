# Typed prompt generator spike

Run `/tmp/opencode/llmcmd-dotnet11/dotnet build spikes/TypedCommands/Sample/Sample.csproj`, `/tmp/opencode/llmcmd-dotnet11/dotnet run --project spikes/TypedCommands/Sample/Sample.csproj`, and `DOTNET_HOST_PATH=/tmp/opencode/llmcmd-dotnet11/dotnet python3 spikes/TypedCommands/Tests/run.py` from the workspace root. Test results and per-case logs go to `/tmp/opencode/llmcmd-typed/`. The generator targets netstandard2.0 and pins Microsoft.CodeAnalysis.CSharp 4.8.0. The consumer and compiler tests use C# 15 on .NET 11, tested with SDK 11.0.100-rc.3.26522.148. The generator implementation remains C# 11 for its netstandard2.0 analyzer target.

The sample demonstrates atomic typed `Bind` and a generated fixed-order chain with conventional `WithCustomer` style names. Nullable annotations are preserved. Required arguments determine staged steps; optional defaults are carried into `Bind` and `Bound`, with optional immutable setters after binding. An optional parameter without an explicit default produces a diagnostic. Each stage has only the next setter; `Build` appears only on the final stage. `WithModel` is optional after binding. The ID and raw template are separate constants. The one-argument attribute defaults the ID to the fully qualified class name. Renaming or moving the class changes that ID; use an explicit ID for durable identity. The generator validates required parameter names against placeholders, allows repeated placeholders and rejects unresolved placeholders, and treats doubled braces as literals. This spike does not render templates or execute models. Its brace grammar is deliberately small, not a claim of compatibility with any template engine. Provider overrides would need their own runtime validation because compile-time validation only sees the constant template.

Arbitrary-order chains need a state model representing which parameters have been supplied. Generating a type for every subset can create up to 2^N states. Generic typestate is a viable alternative: a generic builder carries one state per parameter, and generated extension methods can expose setters for missing states and Build only for the fully present state. Such a design can emit polynomial-sized source without a named class for each subset, although instantiated combinations may grow. See the separate `spikes/ArbitraryOrder` proof. This fixed-order example is a spike choice and does not prove arbitrary mutable fluent flows. Atomic `Bind` is the simpler scalable baseline.

Prototype constraints: top-level static partial classes in namespaces, one static partial void Define with ordinary value parameters, and simple identifiers. Parameter types, accessibility, collisions, nullability, identifier escaping, nested/generic classes, diagnostic locations, stable versioning and generated API compatibility need hardening before production. The public Bound record and reference arguments do not guarantee non-null values. The fluent proof concerns argument presence and static types, not runtime semantic validity. This is not integrated with MEAI or the executor.
