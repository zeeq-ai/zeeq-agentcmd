# Serializer precompile spike

Import `spikes/CommandRoot/build/LlmCmd.Precompile.targets` in a consumer project. The import resolves references, compiles the precompile tool with the pinned .NET 11 SDK, and runs it before `CoreCompile`. It supplies the consumer's `Compile` items, reference assemblies, and preprocessor symbols as separate UTF-8 line files. Paths with spaces are supported. The generated context is added as a normal compile item under the consumer's intermediate output directory; it is rewritten only when its contents change.

The tool finds concrete direct subclasses of `CommandRoot.PromptCommand<TParameters,TResult>` through Roslyn symbols. It generates `internal partial LlmCmd.Generated.LlmCmdJsonContext` with one `JsonSerializable` attribute for each distinct parameter and result root. Each `TypeInfoPropertyName` is `Type_` followed by the lowercase full SHA-256 hex digest of the UTF-8 bytes of the symbol's `ToDisplayString(SymbolDisplayFormat.FullyQualifiedFormat)`. STJ discovers nested types from those roots. The context uses default naming and ignore options and enables `RespectNullableAnnotations`. An explicit application context can coexist; selection is the command generator's responsibility.

The tool's four arguments are source-list path, reference-list path, defines-list path, and output path. Unresolved command type arguments produce `LLMCMDPRE001`; other C# errors remain the compiler's responsibility. The tool does not use runtime reflection or make network calls. It requires SDK `11.0.100-rc.3.26522.148` and uses that SDK's Roslyn assemblies.

Run the isolated proof with `python3 tests/PrecompileProof/run.py`. It writes JUnit and logs under `/tmp/opencode/llmcmd-precompile/`. The proof uses actual STJ generated metadata with reflection serialization disabled.

This is a build-time prototype. It recompiles and scans on each normal build. A design-time build includes an existing generated context but does not create or refresh it, so an initial normal build is needed and changes may remain stale in the IDE until the next normal build. Commands produced by another source generator in the same compilation cannot be discovered. The reserved context name must not be defined by the consumer. It is intended for the pinned net11/C#15 setup; broader SDK, IDE, multi-targeting, and unusual path-character support need separate validation. Serializer context generation does not supply command-specific contract modifiers or validation.
