The management API is the HTTP surface used by the AgentCmd console. It stores build and evaluation definitions, retained execution evidence, and evaluation job state. Applications execute typed commands through the [C# API](/reference/api-cheat-sheet).

## Connect and inspect the contract

Start the loopback API with `mise run console:api:local`. Resource paths use `/api/v1`. The live OpenAPI document is served separately at `/openapi/v1.json`. The console generates its client from the [checked-in OpenAPI snapshot](https://github.com/zeeq-ai/zeeq-agentcmd/blob/main/src/Zeeq.AgentCmd.Console.Client/openapi.json).

```sh
origin=http://127.0.0.1:5180
api="$origin/api/v1"

curl -fsS "$api/workspace"
curl -fsS "$origin/openapi/v1.json" -o agentcmd-openapi.json
```

**Local mode** accepts loopback connections, Host authorities, and browser origins. Its default actor and scope are `local-operator` and `local/dev/default`.

**External mode** requires the host to install authentication middleware through `ControlPlaneApplication.Build(args, configure)`. The authenticated principal supplies a subject and an `agentcmd.permission` claim for the action. Send `X-AgentCmd-Application`, `X-AgentCmd-Environment`, and `X-AgentCmd-Partition` to select a scope allowed by the corresponding `agentcmd.application`, `agentcmd.environment`, and `agentcmd.partition` claims.

## Read stored records and update a draft

Resource reads return an envelope with the ID, state, revision, content hash, and resource body. Fetch a single resource by ID for its stored revision and `ETag`. List responses are scoped and bounded. Set `dataset_id` to an ID from the dataset list. Persist the dataset ID and revision used for evaluation so you can reopen the same frozen dataset later.

```sh
curl -fsS "$api/executions"
curl -fsS "$api/datasets"
curl -fsS -i "$api/datasets/$dataset_id"
```

Use the returned `ETag` as `If-Match` on draft updates and transitions that require a revision. For example, a read that returns `ETag: "3"` supplies the header `If-Match: "3"`. A missing revision returns HTTP 428. A stale revision returns HTTP 409. Re-read the resource and inspect the intervening change before retrying. Frozen definitions are immutable.

## Capture an execution into a regression draft

A trusted host can send retained evidence to `POST /api/v1/executions/observe` with `Operations.Manage`. For production runs that will be curated later, include authorized typed input, its source family, and any retained asset hashes. When the host reports a stored output, include the exact output reference and value.

The curator later creates a regression draft and captures the retained execution. Set `execution_id` to a retained execution ID from your scope.

```sh
curl -fsS "$api/executions/$execution_id"

curl -fsS "$api/datasets" \
  -H 'Content-Type: application/json' \
  --data '{"name":"Extraction regression","body":{"purpose":"Regression","cases":[]}}' \
  -o draft.json

jq '{
  datasetDraftId: .id,
  datasetRevision: .revision,
  reason: "Review the extracted value against the source"
}' draft.json |
  curl -fsS "$api/executions/$execution_id/capture-incident" \
    -H 'Content-Type: application/json' --data-binary @- -o incident.json

jq '{caseId, datasetId: .dataset.id, reviewId: .review.id, alreadyPresent}' incident.json
```

Capture requires `Data.Curate`. The capture endpoint uses `datasetRevision` in the request body. Its response contains the draft, review, case ID, and whether the case already existed. It copies the retained input and asset references and links to the original execution. The expected answer is entered separately from source evidence.

Accept the case by claiming the review via `POST /reviews/{id}/claim` and calling `POST /reviews/{id}/accept-incident` as its owner. Use the current review revision in `If-Match` on both actions. Acceptance requires both `Data.Curate` and `Evaluation.Review`. To record the expected answer, use `PUT /datasets/{id}` with the current draft ETag and a body containing the updated definition. Then freeze the saved revision with `POST /datasets/{id}/freeze`. See the [console walkthrough](/guides/management-console) for the matching screens.

## Endpoint groups

The paths below are relative to `/api/v1`. Consult OpenAPI for exact request and response schemas.

| Task | Main endpoints |
| --- | --- |
| Read workspace and readiness | `GET /workspace`, `GET /health` |
| Register command structure | `POST /builds`, `GET /builds/{id}` |
| Manage evaluation inputs and criteria | `GET /datasets/{id}`, `POST /datasets`, `PUT /datasets/{id}`, `POST /datasets/{id}/freeze`. Use the corresponding `/benchmarks` routes for criteria. |
| Review stored evidence | `GET /executions/{id}`, `GET /reviews/{id}`, `POST /reviews/{id}/claim`, `POST /reviews/{id}/decide` |
| Grade an exact retained execution | `POST /assessments/deterministic`, `POST /assessments/human`, `POST /assessments/llm`, `GET /assessments/{id}` |
| Launch and monitor evaluation | `POST /jobs`, `GET /jobs/{id}`, `POST /jobs/{id}/cancel`, `POST /jobs/{id}/resume`, `GET /comparisons/{id}/summary` |
| Dispatch work from a registered worker | `POST /workers/claim`, `POST /workers/attempt-start`, `POST /workers/attempt-finish`, `POST /workers/complete-work` |
| Manage publication definitions and delivery | `POST /publications`, `POST /publications/{id}/freeze`, `GET /publication-targets`, `GET /publication-operations/{id}` |

## Separate evaluation from execution

`POST /jobs` records approved work. A compatible registered worker claims it and executes through the application's typed command or judge adapter. A backtest runs candidates with pinned frozen inputs. A reassessment points to original outputs and can use deterministic, human, or judge assessment. Creating a job does not load a command or run a provider in the API process.

For historical feedback through the C# library, read the exact version with `IHumanFeedbackLedger.ReadOutput(outputRef, actor)`. For an aggregate, use the whole's published output reference. For dataset replay, use the frozen case input and the benchmark's explicitly chosen reference and criteria.

Acceptance holdouts can appear withheld in API and console projections. An authorized reveal records source-family exposure. It changes independent acceptance eligibility, so use a regression draft for ordinary incident capture.
