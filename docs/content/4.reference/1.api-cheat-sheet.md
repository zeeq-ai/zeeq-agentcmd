This is a map of the maintained APIs, not a generated member listing. The [examples](/examples) show them in context. Current packages are local `0.1.0-alpha.1` artifacts; see [Installation](/getting-started/installation) for the local feed.

## Author and register

| API | Purpose |
| --- | --- |
| `PromptCommand<TParameters, TResult>` | Base for a typed partial command. Declare a stable `Id` and `UserTemplate` as constants. |
| `[PromptCommand(...)]` | Optional explicit ID, revision, profile or `JsonContext` on a command. |
| `AddLlmCmd(...)` | Configure clients, profiles, actor access and stores on `IServiceCollection`. |
| `AddGeneratedCommands()` | Register the generated application command catalog and composition descriptors. |
| `[ModelProfile("id")]` | Declare a typed `ProfileKey` in a generated partial profile catalog. The host still registers its route. |

The source declarations and the application registration use the namespace `Zeeq.LlmCmd`; generated registration is in `Zeeq.LlmCmd.Generated`. See `examples/Zeeq.LlmCmd.CommandExample/` for the full project.

```csharp [Command declaration]
using Zeeq.LlmCmd;

namespace InvoiceDemo;

public sealed record InvoiceParameters(string Document, string Locale = "en");
public sealed record Invoice(decimal Total, string Currency, int Count = 3);

public sealed partial class ExtractInvoice : PromptCommand<InvoiceParameters, Invoice>
{
    const string Id = "invoice.extract";
    const string UserTemplate = "Extract an invoice from {Document} ({Locale}).";
}
```

Optional typed hooks include `static string? Validate(TParameters)` and `static string? Validate(TResult)`. A command can also implement `static partial void ConfigureDefaults(ChatSettingsPatch defaults)`; invocation overrides are applied separately. Hook failures become execution failures. See `tests/Zeeq.LlmCmd.TestFixtures/ContractExamples.cs` and `CommandRoot.cs`.

## Configure clients and profiles

| API | Purpose |
| --- | --- |
| `UseChatClient(factory)` | Single-client path. The runtime owns the returned client. |
| `AddChatClient(name, factory, fixedModel?, classify?)` | Named, runtime-owned client pipeline. The factory creates a new client. |
| `AddChatClient(name, serviceKey?, fixedModel?, classify?)` | Named reference to a keyed DI client. The host owns it. |
| `AddProfile(nameOrKey, client, model, defaults?, retry?, fallback?, attemptTimeout?)` | Route a named profile to a named client and model. |
| `AddProfile(nameOrKey, model, temperature?)` | Single-client profile overload, without a client name. |
| `UseDefaultProfile(...)`, `UseActor(...)`, `UseBudget(...)` | Set the default route, trusted actor accessor and named-route execution budget. |

`IChatClient` and its MEAI middleware remain the execution boundary. `fixedModel` is an explicit binding, not inferred from a deployment name. Runtime configuration checks profile membership, fallbacks and bindings. The client analyzer can additionally diagnose statically provable setup errors; see [Diagnostics and limits](/reference/diagnostics-and-limits).

## Invoke and inspect

```csharp [Invocation]
var outcome = await command.WithParameters(parameters)
    .WithProfile("extraction")
    .ExecuteAsync(cancellationToken);
```

`WithParameters`, `WithProfile`, `WithTemperature`, `Configure`, `InContext`, `InRun` and `WithoutContext` return immutable invocation copies. Only `ExecuteAsync` runs work and captures the call context. Explicit context replaces ambient context as a whole; correlation does not grant authority.

`Outcome<TResult>.Success` carries `Value`, `Snapshot`, `Context` and `Delivery`. Delivery is separately `OutputDelivery.Stored`, `Rejected` or `Failed`. `Outcome<TResult>.Failed` carries an `ExecutionFailure`, including the original context and failure kind. `Map` and `Bind` preserve failure provenance; mapping a value does not persist a new artifact.

## Compose and evaluate

| API | Purpose |
| --- | --- |
| `[CompositeOutput("id", Revision = 1)]` | Declare a partial whole record; generated methods name its slots. |
| `IRootCommands.BeginAsync<TWhole>(CompositionRequest, ...)` | Open a draft for a run, input revision, key and optional trial. |
| `WithHeaderFrom(...)`, `ReuseHeader(...)` | Examples of generated slot methods; actual names follow whole properties. |
| `root.Steps.LineItems.Then(...)` | Build a dependent invocation from an exact `Pinned<T>` stored prerequisite. |
| `root.ExecuteAsync()` | Freeze, validate, execute and publish the plan. Registration itself does not send a request. |
| `CompositeOutcome<TWhole>.Published` | Exposes the aggregate reference, typed value, member lineage and step evidence. Other cases describe incomplete, conflicting, unavailable, configuration-failed or cancelled work. |
| `IHumanFeedbackLedger.ReadOutput` / `RecordGrade` | Read and grade an exact `OutputRef` under an actor. Use the published aggregate reference when grading the whole. |
| `ICompositionStore` | Replaceable storage boundary for drafts, claims, attachments and publication. The default is in memory. |

The full readback and grade example is in [Assemble and grade a whole](/examples/composition). An output reference is not an authorization credential. A composition's producer is its own draft, not a component's execution ID.

## Provider and observability seams

`Zeeq.LlmCmd.Providers` normalizes per-attempt evidence separately from command execution:

- `IProviderResponseAdapter` reads provider wire JSON and enriches canonical usage and diagnostics.
- `INativeResponseProjector` optionally projects an SDK-native response to wire-shaped JSON.
- `IExtractionSink` observes normalized extraction results. `ProviderExtractionChatClient` is a MEAI delegating client; place per-attempt capture next to the provider, inside retry, fallback and tool loops.
- `ProviderExtractionOptions` controls bounded raw-content capture and an isolated failure observer. Raw content is off by default.

`Zeeq.LlmCmd.OpenTelemetry` supplies optional instrumentation, Langfuse generation and propagation adapters. Missing usage or prices stay unknown. Pricing estimates use declared scope and are not a billing ledger or invoice.

Default metadata is generated; an exceptional contract can select an authored `JsonSerializerContext` through `PromptCommand.JsonContext` or `CompositeOutput.JsonContext`. See [Diagnostics and limits](/reference/diagnostics-and-limits) for the supported boundary and NativeAOT evidence.
