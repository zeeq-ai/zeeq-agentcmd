## The problem: the prompt is not the whole operation

An invoice extractor starts with a document and returns a total. MEAI already supports typed responses with `GetResponseAsync<T>`, JSON schema helpers, and middleware. You can use those directly. As the application grows, you may also need a stable prompt identity, captured parameters, a delivery receipt, and a way to evaluate the exact whole that was stored. If each concern lives in a different helper, a reviewer must reconstruct one call from several places.

```csharp [Scattered prompt excerpt]
// Application code must keep the prompt, parse rules and any audit data in sync.
var prompt = $"Extract the total from {document}";
var response = await chatClient.GetResponseAsync(prompt, cancellationToken: ct);
// Parse and validate the response; record the prompt and result separately.
```

With LlmCmd, the authored command keeps the identity and intent beside its parameter and result types. The generator supplies the contract and registration.

```csharp [ExtractInvoice.cs] {4-8}
public sealed record InvoiceInput(string Document);
public sealed record Invoice(decimal Total, string Currency);

public sealed partial class ExtractInvoice : PromptCommand<InvoiceInput, Invoice>
{
    const string Id = "invoice.extract";
    const string UserTemplate = "Extract the invoice from {Document}.";
}
```

```csharp [Call site] {2-4}
var result = await extractInvoice
    .WithParameters(new InvoiceInput(document))
    .ExecuteAsync(ct);
```

The call-site snippet assumes an injected `ExtractInvoice`, a document and a cancellation token. The [quick start](/getting-started/quick-start) supplies the complete host and an offline client.

## Why a command?

LlmCmd borrows a useful idea from `SqlCommand`: give a string-based operation an identity, parameters, execution, and a result. It is an analogy, not a claim that model output is deterministic or that prompting has SQL transactions. A typed result still needs validation, and a provider call can fail or incur cost after cancellation.

The library extends [Microsoft.Extensions.AI](https://learn.microsoft.com/en-us/dotnet/ai/microsoft-extensions-ai) (MEAI). You supply an `IChatClient`; its middleware can still handle retries, caching, tools, and telemetry. LlmCmd adds a typed command and execution contract around that pipeline. Provider accounting and OpenTelemetry are optional packages, not dependencies a provider must know about.

## Where it helps

- **Extract one structured result:** keep an invoice prompt and its input/output contract together, then inspect a typed outcome.
- **Use several clients:** route an extraction and a review to separate client pipelines and model profiles.
- **Assemble a whole:** extract a header, parties and lines separately; run a totals step using the stored line result; grade the exact published invoice.

Use a direct `IChatClient` call, including MEAI's typed-response helpers, when it meets your needs without LlmCmd's command identity, capture, delivery outcomes, or aggregate composition. LlmCmd does not make a provider deterministic or supply a durable ledger by default.

::note
The default ledger and composition store are in memory. They do not provide process-restart recovery, distributed leases, or exactly-once provider billing.
::
