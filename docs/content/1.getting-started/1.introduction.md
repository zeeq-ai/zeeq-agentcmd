## Why use LlmCmd?

Imagine an application that reads an invoice and asks a model to extract its total. The first version may be a prompt and a call to a chat client. Then an invoice comes back with the wrong total, and someone asks a few reasonable questions:

- Which prompt and input produced this result?
- Which model was used, and did the call get retried?
- Can we read and evaluate the exact result that was stored?

Those questions get harder when the prompt, its inputs, the model call, and the result live in different helpers. For a document assembled from several calls, there is one more question: **which result is the whole invoice?** A trace of the last call is not the invoice the application uses.

LlmCmd gives that operation a home. Think of a command as a small recipe: it names the prompt, describes the input and output, and knows how to run through your chat client. Afterward, you can inspect its captured user prompt, inputs, and result. You can also compose several commands into a whole and evaluate the stored whole.

Microsoft.Extensions.AI (MEAI) already offers typed responses, JSON schema helpers, and middleware. LlmCmd builds on those APIs. It adds the command identity, captured inputs, delivery receipt, and composition and evaluation boundaries around them.

```csharp [Scattered prompt excerpt]
// The application keeps the prompt and its audit data together itself.
var prompt = $"Extract the total from {document}";
var response = await chatClient.GetResponseAsync(prompt, cancellationToken: ct);
// Parse the response and retain the inputs if you need them later.
```

That can be perfectly reasonable for a small call. But if the same operation needs to be reused, observed, and evaluated across an application, there is more to keep in sync. With LlmCmd, the declaration keeps the intent and types together:

```csharp [ExtractInvoice.cs] {5,7-8}
public sealed record InvoiceInput(string Document);

public sealed record Invoice(decimal Total, string Currency);

public sealed partial class ExtractInvoice : PromptCommand<InvoiceInput, Invoice>
{
    const string Id = "invoice.extract"; // Stable even if the class is renamed.
    const string UserTemplate = "Extract the invoice from {Document}.";
}
```

```csharp [Call site] {2-3}
var result = await extractInvoice
    .WithParameters(new InvoiceInput(document)) // Supply this invocation's input.
    .ExecuteAsync(ct); // The model call happens here.
```

The generator supplies the schema, serializer metadata, and registration. `result` contains a typed outcome and, when available, the captured prompt and parameters. The call site above assumes an injected command, a document, and a cancellation token. The [quick start](/getting-started/quick-start) builds the complete example with an offline client.

## Why a command?

LlmCmd borrows a useful idea from `SqlCommand`: give a string-based operation an identity, parameters, execution, and a result. It is a familiar way to put the parts of an operation in one place.

The analogy has limits. Model output is not deterministic, and a prompt is not a SQL transaction. A typed result still needs validation. A provider call can fail or incur cost after cancellation.

The library extends [Microsoft.Extensions.AI](https://learn.microsoft.com/en-us/dotnet/ai/microsoft-extensions-ai) (MEAI). You supply an `IChatClient`; its middleware can still handle retries, caching, tools, and telemetry. LlmCmd adds a typed command and execution contract around that pipeline. It creates command and routing activities during execution. Optional provider extraction and OpenTelemetry packages let the host capture attempts and select an exporter without coupling a provider to a collector.

## Where it helps

- **Extract one structured result:** keep an invoice prompt and its input/output contract together, then inspect a typed outcome.
- **Use several clients:** route an extraction and a review to separate client pipelines and model profiles.
- **Observe and evaluate a run:** capture provider attempts, inspect prompt inputs, and read the exact stored output for a grade.
- **Assemble a whole:** extract a header, parties and lines separately; run a totals step using the stored line result; grade the exact published invoice.

Use a direct `IChatClient` call, including MEAI's typed-response helpers, when it meets your needs without LlmCmd's command identity, capture, delivery outcomes, or aggregate composition. LlmCmd does not make a provider deterministic or supply a durable ledger by default.

::note
The default ledger and composition store are in memory. They do not provide process-restart recovery, distributed leases, or exactly-once provider billing.
::
