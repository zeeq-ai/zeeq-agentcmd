An invoice comes back with the wrong total. Where do you start?

You might want to follow the call through a trace, inspect the prompt and invoice text that were used, and then run a check against the *same output* the application stored. If the provider was retried, you may also want to see each attempt and its reported token usage.

LlmCmd helps you collect those pieces without repeating the wiring at every command call site. The host still chooses where telemetry goes and which records to retain. Let's look at what is available and how the pieces fit together.

## What is captured, and where does it go?

```text [One command or composition]
ExecuteAsync
  ├─ command and attempt activities → host's OpenTelemetry exporter → collector
  ├─ command snapshot → outcome → host's optional input/evaluation record
  ├─ provider extraction middleware → normalized attempt → host's extraction sink
  └─ successful output → feedback ledger → exact OutputRef → evaluation
```

LlmCmd creates command and routing activities as work executes. A listener or tracer provider must be configured to record and export them. The command outcome carries an `ExecutionSnapshot` when execution reached the relevant stages: prompt ID, revision, definition hash, raw user template, rendered user prompt, parameters, profile, model and routing evidence where available. A failed outcome can have a partial snapshot or none.

Provider extraction is an **opt-in** MEAI middleware. Once registered at the provider boundary, it observes each call through that pipeline without adding capture code to each command call site. Its `ResponseSnapshot` contains provider and protocol identity, attempt ID, model and response IDs, usage evidence, content counts and diagnostics. Raw response text is off by default.

An `OutputDelivery.Stored` receipt identifies an output accepted by the configured `IHumanFeedbackLedger`. The ledger stores output JSON and feedback; it does **not** automatically persist the command snapshot or the provider snapshot. A composition also retains component lineage and publishes a separate whole output. The default ledger and composition store are in memory.

::note
Telemetry is best effort. A span, observer callback or successful command does not prove that an exporter delivered data or that an output was durably stored. Check the output delivery or composition publication receipt separately.
::

## Capture every provider attempt

Register `UseProviderExtraction` last in a `ChatClientBuilder`, directly above the provider. Put retry, fallback and tool-loop middleware outside it. Each actual provider call is then observed separately, including failed and cancelled attempts. The wrapper returns the provider response unchanged and isolates adapter and sink failures.

```text [Pipeline placement]
Application → retry / fallback / tool loop → attempt capture → provider client
```

The [offline capture example](/examples/telemetry-and-evals) shows a keyed client, an `IExtractionSink`, a generated command and stored-output grading. Its setup also exposes `ProviderExtractor.Extract` for a complete response the host already has. Use the manual path when middleware is not appropriate; avoid publishing the same observation twice. `Extract` accepts an explicit wire JSON body when available and an attempt ID supplied by the host.

Three independent seams make this work across providers and destinations:

- `IProviderResponseAdapter` reads a registered provider's wire protocol into canonical usage and diagnostics. The built-in adapters cover OpenAI-compatible Chat Completions, Anthropic Messages and DeepSeek Chat; choose the provider and API explicitly.
- `INativeResponseProjector` is an optional host-supplied bridge from an SDK-native response to its wire-shaped JSON. Without a usable native response or projector, normalized MEAI fields can still be captured, but provider-specific details may be missing.
- `IExtractionSink` receives the normalized `ExtractionResult`. It can feed a collector adapter or a host-owned record store without making the provider adapter depend on that destination.

An extraction result can be `Extracted`, `Partial` or `Invalid`; each carries a snapshot and diagnostics. Missing usage remains unknown. `ProviderExtractionOptions.OnFailure` can report isolated extractor or sink failures. Protect or sanitize any information your observer records.

The extraction middleware assigns its own `ResponseSnapshot.AttemptId`; do not assume it equals an `ExecutionEvent.AttemptId` from the command router. An extraction sink also does not receive the command snapshot or output. If a destination needs those records joined, carry the relevant captured trace context and host correlation information with the observation. Do not look up a later ambient scope after queuing it.

## Subscribe and export traces

Add the local `Zeeq.LlmCmd.OpenTelemetry` package to the host. It includes the provider package and OpenTelemetry dependencies. The following host helper resolves a Langfuse target using the application's `ISecretSource`, subscribes to LlmCmd sources, and configures an OTLP trace exporter. The secret references are names, not credential values.

```csharp [TelemetryExport.cs]
using System.Diagnostics;
using OpenTelemetry;
using OpenTelemetry.Trace;
using Zeeq.LlmCmd.OpenTelemetry;
using Zeeq.LlmCmd.Providers;

namespace QuickStart;

public static class TelemetryExport
{
    public static async Task<TracerProvider> CreateTracerAsync(
        ISecretSource secrets,
        CancellationToken cancellationToken = default
    )
    {
        // Resolve named secrets without putting credentials in the options.
        var resolved = await Profiles.ResolveAsync(
            new TargetOptions.Langfuse(
                Profiles.LangfuseCloud,
                new SecretRef("langfuse-public"),
                new SecretRef("langfuse-secret")
            ),
            secrets,
            Signal.Traces,
            cancellationToken
        );
        if (resolved is not ConfiguredTarget target)
        {
            throw new InvalidOperationException(
                "The telemetry target is not configured."
            );
        }

        // Subscribe to LlmCmd activities, then choose where to export them.
        return Sdk.CreateTracerProviderBuilder()
            .AddLlmCmdInstrumentation()
            .AddOtlpExporter(options =>
            {
                if (target.Configure(Signal.Traces, options) is not null)
                {
                    throw new InvalidOperationException(
                        "The trace exporter is not configured."
                    );
                }
            })
            .Build();
    }

    public static void EmitGeneration(
        ResponseSnapshot snapshot,
        ActivityContext parent,
        DateTimeOffset started,
        DateTimeOffset ended
    )
    {
        // Use the parent and times captured for this attempt, even after a queue.
        LangfuseGeneration.EmitSafely(
            snapshot,
            parent,
            started,
            ended,
            promptName: "invoice.extract",
            promptVersion: 1
        );
    }
}
```

The host supplies and protects the secrets, keeps the returned tracer provider alive for the application lifetime, and disposes or flushes it during shutdown. `AddLlmCmdInstrumentation()` subscribes to command, routing, evaluation, propagation and Langfuse activity sources. Its meter-provider overload subscribes to routing metrics; configure a metrics exporter separately when the destination supports metrics.

`TargetOptions` also provides LangSmith, Braintrust, Logfire and generic OTLP profiles. The resolver checks endpoint shape, credential references and the requested signals. Langfuse and LangSmith profiles support traces; Braintrust supports traces and logs; Logfire and generic OTLP support traces, metrics and logs. These are exporter configurations, not proof that a hosted service accepted a record.

The Langfuse generation adapter is a separate, explicit mapping. Call `EmitGeneration` with a completed snapshot and the **captured** parent context and timestamps for that attempt. A host that queues observations must carry those values across the handoff; `IExtractionSink` supplies the extraction result but does not supply attempt timestamps. `EmitSafely` isolates observation failures. It emits agreed token totals and, when supplied, a complete USD cost estimate; it does not export prompt or response text.

## Retain the evidence needed for evaluation

Use the outcome's snapshot to inspect or deliberately retain the raw user template, rendered prompt and parameter records. `Outcome<T>.Success` also contains the validated value and a separate delivery receipt. For a leaf, `OutputDelivery.Stored.Output.Reference` identifies the exact stored provider JSON. A successful value with a rejected or failed delivery is not a stored evaluation artifact.

For a whole, use `CompositeOutcome<TWhole>.Published.Aggregate.Output`. Read that reference through the ledger under an authorized actor, then grade the whole or a JSON pointer within it. Component references remain useful for lineage; they do not replace the aggregate reference. The [composition example](/examples/composition) reads the stored whole and checks its grade and replay receipts.

If later evaluations need inputs as well as results, persist the command snapshot through a host-owned capture path and associate it with the run and execution identity. The [offline example](/examples/telemetry-and-evals) defines an application-owned input-store interface, saves the snapshot with the exact output reference, and reads that output for grading. Its store is in memory; production hosts choose their own persistence and write-failure policy.

A custom `IExecutionEventSink` can observe lifecycle events, but those events do not contain the full snapshot or output. It is best effort; it is not a durable journal. Replace `IHumanFeedbackLedger` and, for durable compositions, `ICompositionStore` with host implementations that enforce authorization, versioning and retention.

Treat prompts, parameters, output JSON and captured response text as potentially sensitive. Choose access, redaction and retention policies before storing or exporting them. Raw provider text is disabled by default; enabling `RawContentPolicy` captures bounded response items, not tool arguments. The built-in Langfuse generation adapter does not automatically send those contents.

## Usage, cost and limits

`PricingEstimator.Estimate(snapshot, scope)` combines observed usage with an explicit `PricingScope`, model binding and rate-card provenance. The estimate can be complete, partial or unpriced. Missing counts or prices are unknown, never zero. A token estimate is not invoice reconciliation.

Native streaming accounting and OpenAI Responses extraction have explicit limits. The repository's local Langfuse test has sent and read back a generation from a self-hosted instance. Other collector profile tests verify OTLP requests against a local handler; they do not establish hosted-service readback. The package-only NativeAOT proof uses synthetic clients and does not establish NativeAOT support for every vendor SDK.
