`ExecuteAsync` returns `Outcome<TResult>`. Its two top-level cases are `Success` and `Failed`.

```csharp [OutcomeInspector.cs]
using QuickStart;
using Zeeq.LlmCmd;

public static class OutcomeInspector
{
    public static void Inspect(
        Outcome<Invoice> outcome,
        IHumanFeedbackLedger ledger,
        Actor actor
    )
    {
        switch (outcome)
        {
            case Outcome<Invoice>.Success success:
                var rawTemplate = success.Snapshot.RawTemplate;
                var parameters = success.Snapshot.Parameters;
                Console.WriteLine($"Template length: {rawTemplate.Length}; parameters: {parameters.Count}");

                switch (success.Delivery)
                {
                    case OutputDelivery.Stored stored:
                        var outputRef = stored.Output.Reference;
                        if (ledger.ReadOutput(outputRef, actor) is LedgerResult<OutputArtifact>.Accepted)
                        {
                            Console.WriteLine("The exact output version was read.");
                        }
                        break;
                    case OutputDelivery.Rejected rejected:
                        Console.WriteLine($"Storage rejected: {rejected.Code}");
                        break;
                    case OutputDelivery.Failed:
                        Console.WriteLine("Storage failed; the model value may still be valid.");
                        break;
                }
                break;
            case Outcome<Invoice>.Failed failed:
                Console.WriteLine($"Command failed: {failed.Failure.Kind}");
                break;
        }
    }
}
```

The example uses the `Invoice` from the quick start and a host-supplied ledger and actor. `RawTemplate` is the unrendered template; each `ParameterRecord` carries a name and serialized value. Both can contain sensitive information, so apply your host's access and retention policy before displaying or storing them.

Success contains the validated value, execution snapshot, caller and a separate output-delivery receipt. A value being valid does not itself mean it was stored. Failure retains its original execution context. `Map`, `Bind` and `BindAsync` forward the original failure; `Map` does not create a new stored output.

Failures include invalid input, provider failure, invalid output, invalid configuration, hook failure and cancellation. Handle the case that matters to your application instead of assuming every failure came from the provider.

## Capture context once

A context correlates an operation with a run. It is captured when `ExecuteAsync` starts. An explicit context replaces the ambient context as a whole; it does not merge individual fields.

```csharp [Context excerpt]
using var scope = LlmCmdContext.BeginScope(OperationContext.ForRun(runId));

var ambient = await command.WithParameters(input).ExecuteAsync(ct);
var explicitRun = await command.WithParameters(input).InRun(otherRunId).ExecuteAsync(ct);
var without = await command.WithParameters(input).WithoutContext().ExecuteAsync(ct);
```

These calls assume the host has created and authorized the runs. A context is **correlation**, not permission or composition membership. The trusted `Actor` and the ledger or store make authorization decisions; registering a slot makes a command part of a composition. An observer receives the captured context rather than reading a later ambient scope.

`WithParameters`, `WithProfile`, `InContext`, `InRun` and `WithoutContext` create immutable invocations. Branching one does not change the other. Explicit context is not a guarantee that output persistence succeeded; inspect the delivery receipt.
