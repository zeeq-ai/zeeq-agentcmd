Some documents are too complicated for one useful extraction. You might ask one command for the header, another for the parties, and a third for the line items. Then a totals command needs the line count before it can do its work.

How do those separate answers become the invoice your application actually uses? Composition lets you describe the parts and their dependencies, then publish **one whole result**. It keeps the individual parts' lineage as well, so you can inspect a step without mistaking that step for the finished invoice.

## Declare the whole

```csharp [Commands.cs]
using System.Text.Json.Serialization;
using Zeeq.AgentCmd;

namespace CompositionDemo;

[CompositeOutput("invoice.composite", Revision = 1)]
public sealed partial record DocumentExtraction(
    // The JSON field can have a different name from the C# property.
    [property: JsonPropertyName("header_data")] Header Header,
    Parties Parties,
    LineItems LineItems,
    Totals Totals
);
```

`Header`, `Parties`, `LineItems` and `Totals` are application result types. Their property names determine generated methods such as `WithHeaderFrom`; the JSON name can differ. Declare leaf commands that produce each part, then add the generated catalog to the host as in the [quick start](/getting-started/quick-start).

## Register, then execute

The full runnable example declares `ExtractHeader`, `ExtractParties`, `ExtractLineItems`, `ExtractQuickLineItems` and `ExtractTotals` as partial commands, one for each supported part. For example, the header command looks like this:

```csharp [ExtractHeader.cs]
public sealed partial class ExtractHeader : PromptCommand<SourceText, Header>
{
    // This leaf can be used by itself or attached to a whole.
    public const string Id = "example.header";
    public const string UserTemplate = "HEADER {Document}";
}
```

The types and other commands are in `examples/Zeeq.AgentCmd.CompositionExample/Commands.cs`. The following expandable setup excerpt starts from a host-provided `IChatClient` named `client`. It registers the commands and obtains the values used below.

::code-collapse{label="Host bootstrap"}

```csharp [CompositionBootstrap.cs]
var actor = new Actor("demo", "reviewer");

// Register the client and generated command catalog once for the host.
var services = new ServiceCollection()
    .AddAgentCmd(options =>
        options
            .UseChatClient(_ => client)
            .AddProfile("extract", "synthetic-model")
            .UseActor(_ => actor)
    )
    .AddGeneratedCommands();
using var provider = services.BuildServiceProvider();
var ledger = provider.GetRequiredService<IHumanFeedbackLedger>();
var runId = ledger.CreateRun(actor); // Groups this authorized piece of work.
var roots = provider.GetRequiredService<IRootCommands>();
var header = provider.GetRequiredService<ExtractHeader>();
var parties = provider.GetRequiredService<ExtractParties>();
var lines = provider.GetRequiredService<ExtractLineItems>();
var quickLines = provider.GetRequiredService<ExtractQuickLineItems>();
var totals = provider.GetRequiredService<ExtractTotals>();
var text = new SourceText("example invoice");
```

::

An **actor** is the trusted host identity used for authorization. A **run** groups related work and is created by the ledger. The request's `Key` identifies this composition within its run and input revision; it is not an authorization grant.

This excerpt follows the repository's runnable `examples/Zeeq.AgentCmd.CompositionExample`. `roots`, `runId`, commands, input and the branch decision come from the host.

```csharp [Composition excerpt] {6,10,14,18-20,24}
var root = await roots.BeginAsync<DocumentExtraction>(
    new CompositionRequest(runId, "input-v1", "invoice-42")
);

// Describe the parts. None of these calls sends a request yet.
root.WithHeaderFrom(header.WithParameters(text)).WithPartiesFrom(parties, text);

if (detailed)
{
    root.WithLineItemsFrom(lines.WithParameters(text));
}
else
{
    root.WithLineItemsFrom(quickLines.WithParameters(text));
}

// Totals waits for the exact stored line-item result.
root.WithTotalsFrom(
    root.Steps.LineItems.Then(pinned =>
        totals.WithParameters(new TotalsParameters(text.Document, pinned.Value.Count))
    )
);

var outcome = await root.ExecuteAsync(ct); // Now run and publish the plan.
```

`With…From` registers work on the same bounded construction handle. It does not call a model. `Then` receives the pinned stored result of the prerequisite; the dependent invocation is checked before its own call. A failed dependency blocks the dependent step. Generated `Reuse…` methods can attach an existing compatible `Pinned<T>` instead of starting that part again.

`ExecuteAsync` freezes and validates the plan, checks authorization and claims, runs eligible work and publishes the whole when its requirements are met. Duplicate slot registration is a configuration failure. An optional slot may be absent, but a null part cannot be attached. A repeated handle can replay a published result; this is not a promise of exactly-once provider billing.

## What is stored?

A published aggregate has its own composition producer and an `OutputRef`. Its members retain their leaf lineage. The aggregate is not identified by one leaf's execution ID. Read and grade that exact reference as shown in [Evaluation](/guides/evaluation).

::caution
The default composition store and feedback ledger are in memory. A durable host implementation must provide its own storage and recovery guarantees.
::
