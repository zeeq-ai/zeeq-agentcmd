A **client registration** identifies a complete `IChatClient` pipeline. A **profile** selects a client, a model or deployment, and optional settings. The client name is a case-sensitive routing key; it is not a provider identity or a model name.

## One client

```csharp [Host setup excerpt]
services.AddLlmCmd(options =>
    options
        .UseChatClient(_ => CreateClient())
        .AddProfile("extract", "model-id")
        .UseActor(_ => actor)
);
```

`CreateClient` and `actor` are host-supplied. The runtime owns the client returned by this factory. With one profile, it is the default.

## Several pipelines

The following excerpt assumes host factories `createAzureClient` and `createClaudeClient` return configured `IChatClient` pipelines. The host registers and owns these keyed clients; LlmCmd borrows them.

```csharp [Host setup excerpt] {1-2,6-10}
services.AddKeyedChatClient("azure.luna", createAzureClient);
services.AddKeyedChatClient("claude", createClaudeClient);

services.AddLlmCmd(options =>
    options
        .AddChatClient("azure.luna", fixedModel: "gpt-6-luna")
        .AddChatClient("claude")
        .AddProfile("fast", "azure.luna", "gpt-6-luna")
        .AddProfile("deep", "claude", "claude-model-id")
        .UseDefaultProfile("fast")
        .UseActor(_ => actor)
);
```

The keyed `AddChatClient` overload borrows a singleton-compatible DI client. `AddChatClient("name", sp => CreateClient(sp))` instead transfers ownership of the returned client to the runtime. Do not return a DI-owned client from the owning factory overload.

The OpenAI Chat Completions SDK client is model-bound: register a separate client for each model or deployment and declare `fixedModel`. The Anthropic client can select a model per request. A profile that conflicts with a declared fixed binding fails setup before client factories run. An Azure deployment name alone does not prove the model or price behind it.

## Select and override

```csharp [Invocation excerpt]
var result = await extractInvoice
    .WithParameters(new InvoiceInput(document))
    .WithProfile("deep")
    .WithTemperature(0.1f)
    .ExecuteAsync(ct);
```

The selected profile supplies defaults beneath explicit invocation settings. Command and provider defaults fill remaining settings. A fallback uses its own profile defaults while preserving explicit caller overrides. Configure retries, fallback and attempt timeout on `AddProfile`; `UseBudget` bounds the route across attempts.

The bundled analyzer checks straightforward `AddLlmCmd` lambdas at build time. `LLMCLIENT001` reports a known missing client, `LLMCLIENT002` a duplicate and `LLMCLIENT003` a constant fixed-model conflict. Dynamic configuration, branches and helper-driven registration still use runtime validation. The analyzer does not inspect credentials or contact a provider.

::note
Do not mix the single-client `UseChatClient`/two-argument `AddProfile` mode with named-client routes. The runtime rejects that setup.
::
