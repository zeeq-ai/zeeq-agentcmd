title: Evaluate the stored whole
description: Read and grade the exact aggregate version rather than a component trace.

Imagine the header, line items, and total all look reasonable on their own. The invoice can still be wrong as a whole: perhaps the total was calculated for a different line count. A grade on each individual response would miss that relationship.

For that question, read and grade the **published invoice**. Its output reference identifies the exact stored version, even though several commands helped produce it.

The ledger stores output JSON and feedback against a versioned `OutputRef`. For an ordinary command, the command's prompt and parameter snapshot and the provider's attempt snapshot are separate observations. Retain them through a host-owned capture path when an evaluation needs that input context. Experiment-enabled outputs also carry their experiment evidence in the ledger. A trace can link work, but it is not a substitute for the stored value. See [Telemetry and evaluation capture](/guides/accounting-and-observability).

The following excerpt continues the [composition example](/guides/composition). It assumes `outcome` is the result of `root.ExecuteAsync`, and `provider`, `ledger` and the authorized `actor` come from the host.

```csharp [Evaluate excerpt] {8,10-11,22,32-36}
// No published whole means there is nothing to grade yet.
if (outcome is not CompositeOutcome<DocumentExtraction>.Published published)
{
    throw new InvalidOperationException("The whole was not published.");
}

// Keep the aggregate's own reference, not a component execution ID.
var outputRef = published.Aggregate.Output;
if (
    ledger.ReadOutput(outputRef, actor)
    is not LedgerResult<OutputArtifact>.Accepted stored
)
{
    throw new InvalidOperationException("The stored whole is unavailable.");
}

// Read the stored JSON with the generated whole contract.
var descriptor =
    provider.GetRequiredService<CompositionRegistry>().Find<DocumentExtraction>()
    ?? throw new InvalidOperationException("The whole contract is missing.");
var whole =
    stored.Value.Value.Deserialize(descriptor.Whole)
    ?? throw new InvalidOperationException("The stored whole could not be decoded.");

// This small check is an example; use the rules your invoice needs.
if (whole.LineItems.Count < 0 || whole.Totals.Amount < 0)
{
    throw new InvalidOperationException("The stored invoice failed evaluation.");
}

// An empty JSON pointer targets the root of this stored whole.
var grade = new GradeRequest(
    Guid.NewGuid(),
    outputRef,
    "",
    stored.Value.Value,
    1.0,
    "The stored invoice has a nonnegative line count and total"
);
if (ledger.RecordGrade(grade, actor) is not LedgerResult<GradeReceipt>.Accepted)
{
    throw new InvalidOperationException("The grade was not recorded.");
}
```

The example checks two simple invariants against `whole`. It does not prove that the total matches the line items: this small DTO has a count and total, but no individual amounts to add. In an application with those amounts, you can check that relationship here too.

The empty JSON pointer targets the root; a different pointer can target a part of that same stored output. The `ObservedValue` above is the value read from the ledger. Replaying the same grade event can return a replay receipt.

The aggregate's producer is a composition. Its component execution IDs remain useful lineage, but none is a substitute for the aggregate `OutputRef`. Reconstructing the whole from traces or grading every leaf would ask a different question.

::note
The default ledger is in memory. Use a host-provided `IHumanFeedbackLedger` when your application needs persistence, access control or retention beyond that default.
::
