An invoice comes back with the wrong total. Where do you start?

You might want to follow the call through a trace, inspect the prompt and invoice text that were used, and then run a check against the *same output* the application stored. If the provider was retried, you may also want to see each attempt and its reported token usage.

AgentCmd helps you collect those pieces without repeating the wiring at every command call site. The host still chooses where telemetry goes and which records to retain. Let's look at what is available and how the pieces fit together.

## Choose an emitter

AgentCmd has several seams. Some have built-in destinations and some are host-owned. Pick the seam that matches where you want the data.

| Destination | Seam | Built in? |
| --- | --- | --- |
| Traces to an OTLP collector | `AddAgentCmdInstrumentation` and `TargetOptions` | Yes |
| Langfuse, LangSmith, Braintrust, Logfire or generic OTLP | `TargetOptions` profiles | Yes |
| Langfuse generation with usage and cost | `LangfuseGenerationSink` | Yes |
| A database of provider calls | `IAttemptSink` | Host-owned |
| A database of outputs and grades | `IHumanFeedbackLedger`, `ICompositionStore` | Host-owned |
| Lifecycle events to a queue or log | `IExecutionEventSink` | Host-owned |

There is no built-in database emitter. Storage, retention and access control belong to the host.

## What is captured, and where does it go?

```text [One command or composition]
ExecuteAsync
  ├─ command and attempt activities → host's OpenTelemetry exporter → collector
  ├─ command snapshot → outcome → host's optional input/evaluation record
  ├─ attempt capture middleware → AttemptRecord per provider call → every registered IAttemptSink
  └─ successful output → feedback ledger → exact OutputRef

Later: reviewer selects retained runs → builds dataset → grader reads exact stored outputs
```

AgentCmd creates command and routing activities as work executes. A listener or tracer provider must be configured to record and export them. The command outcome carries an `ExecutionSnapshot` when execution reached the relevant stages: prompt ID, revision, definition hash, raw user template, rendered user prompt, parameters, profile, model and routing evidence where available. A failed outcome can have a partial snapshot or none.

Attempt capture is an **opt-in** MEAI middleware at the provider boundary. It records each provider call without capture code at the command call site. The next section shows what it records.

An `OutputDelivery.Stored` receipt identifies an output accepted by the configured `IHumanFeedbackLedger`. For an ordinary command, the ledger stores output JSON and feedback; it does **not** automatically persist the command snapshot or provider snapshot. For an experiment-enabled command, the output and its experiment evidence are recorded together. A composition also retains component lineage and publishes a separate whole output. The default ledger and composition store are in memory.

::note
Telemetry is best effort. A span, observer callback or successful command does not prove that an exporter delivered data or that an output was durably stored. Check the output delivery or composition publication receipt separately.
::

## Capture every provider call

Attempt capture is an **opt-in** MEAI middleware. It sits directly above the provider, inside retry, fallback and tool-loop middleware, so each actual provider call becomes one record. It includes failed, cancelled and abandoned calls. The wrapper returns the provider response unchanged and isolates adapter and sink failures.

```text [Pipeline placement]
Application → retry / fallback / tool loop → attempt capture → provider client
```

Name the provider protocol when you register the client. AgentCmd builds the pipeline and puts capture innermost:

```csharp [Captured client]
services
    .AddAgentCmd(agent => agent
        .AddChatClient("azure", CreateAzureClient, Protocols.AzureOpenAIChatCompletions,
            configure: pipeline => pipeline.UseFunctionInvocation()) // Wraps capture.
        .AddProfile("extraction", "azure", "invoice-deployment"))
    .AddAttemptSink<AttemptRowSink>();
```

Each finished call goes to every `IAttemptSink` in DI. The command call site stays `WithParameters(...).ExecuteAsync()`. The client name `azure` is also the capture registration ID. `Protocols` has presets for OpenAI and Azure OpenAI Chat Completions, Anthropic Messages and DeepSeek Chat. The protocol stays explicit; it is never inferred from a model name.

For a keyed client the host already owns, add capture last in its builder: `services.AddKeyedChatClient("azure", create).UseAttemptCapture(Protocols.AzureOpenAIChatCompletions, "azure")`. Then reference it with `AddChatClient("azure")`. Without DI, pass an extractor and sinks to `UseAttemptCapture(extractor, identity, sinks)`. To normalize a response the host already has, call `ProviderExtractor.Extract`. Avoid publishing the same call twice.

An `AttemptRecord` holds:

- `Result`: the closed extraction outcome, `Extracted`, `Partial` or `Invalid`. Each case carries the `ResponseSnapshot` and its diagnostics.
- `Snapshot`: provider and protocol identity, call ID, model and response IDs, usage evidence, content counts and diagnostics. Raw response text is off by default. Missing usage remains unknown.
- `Started` and `Ended`: when the call was sent and when it finished. A stream starts on first enumeration and ends when it is disposed.
- `Correlation`: the command and routed attempt that made the call.

Sinks run in order, each isolated, so a collector outage does not stop a database row. `ProviderExtractionOptions.OnFailure` reports isolated extractor and sink failures. Register options in DI to change the raw-content policy or the clock. Protect or sanitize any information your sink records.

Three independent seams make this work across providers and destinations:

- `IProviderResponseAdapter` reads a provider's wire protocol into canonical usage and diagnostics. A `ProviderProtocol` preset bundles the adapter with its provider key and API.
- `INativeResponseProjector` is an optional host-supplied bridge from an SDK-native response to its wire-shaped JSON. Without a usable native response or projector, normalized MEAI fields can still be captured, but provider-specific details may be missing.
- `IAttemptSink` receives each `AttemptRecord`. It can feed a collector or a host-owned record store without making the provider adapter depend on that destination.

`Correlation` has three levels:

- **Command**: `Correlation.Command.ExecutionId`, one per `ExecuteAsync`.
- **Routed attempt**: `Correlation.RouteAttemptId`, one per retry or fallback. It equals `ExecutionEvent.AttemptId`.
- **Provider call**: `Snapshot.AttemptId`. Inner middleware that retries or runs tools can make several calls under one routed attempt, so each call has its own ID.

Capture reads the correlation once, when the call starts. A queued sink or a late, timed-out completion keeps the attempt it started under. `Correlation` is null for a call made outside a command. Use the execution ID to join an attempt to a stored delivery receipt. Read the output through the ledger using the exact reference from that receipt and an authorized actor.

## Subscribe and export traces

Add the local `Zeeq.AgentCmd.OpenTelemetry` package to the host. It includes the provider package and OpenTelemetry dependencies. `TelemetryStartup.CreateTracerAsync` resolves a collector target using the application's `ISecretSource`, subscribes to AgentCmd sources, and configures an OTLP trace exporter. The secret references are names, not credential values.

```csharp [TelemetryExport.cs]
using OpenTelemetry.Trace;
using Zeeq.AgentCmd.OpenTelemetry;

namespace QuickStart;

public static class TelemetryExport
{
    public static Task<TracerProvider> CreateTracerAsync(
        ISecretSource secrets,
        CancellationToken cancellationToken = default
    ) =>
        // Resolves the named secrets, subscribes to AgentCmd sources and exports over OTLP.
        TelemetryStartup.CreateTracerAsync(
            new TargetOptions.Langfuse(
                Profiles.LangfuseCloud,
                new SecretRef("langfuse-public"),
                new SecretRef("langfuse-secret")
            ),
            secrets,
            cancellationToken
        );
}
```

The host supplies and protects the secrets, keeps the returned tracer provider alive for the application lifetime, and disposes or flushes it during shutdown. `AddAgentCmdInstrumentation()` subscribes to command, routing, evaluation, propagation and Langfuse activity sources. Its meter-provider overload subscribes to routing metrics; configure a metrics exporter separately when the destination supports metrics.

`TargetOptions` also provides LangSmith, Braintrust, Logfire and generic OTLP profiles. The resolver checks endpoint shape, credential references and the requested signals. Langfuse and LangSmith profiles support traces; Braintrust supports traces and logs; Logfire and generic OTLP support traces, metrics and logs. These are exporter configurations, not proof that a hosted service accepted a record.

## Emit a generation at the call site

A **generation** is Langfuse's record of one model call: model, token usage, duration and, optionally, cost. You do not emit it from each command call site. Register the built-in sink once:

```csharp [Generation sink]
services.AddAttemptSink<LangfuseGenerationSink>();
```

Each provider call appears under its routed attempt span, with its real start and end. The generation's metadata names the command ID, revision, execution ID, routed attempt and profile. The sink uses the trace context captured when the call started, so a late emission still lands under the right command.

Two behaviors are opt-in, through a `LangfuseGenerationOptions` registered in DI:

```csharp [Generation options]
services
    .AddAgentCmdPricing()
    .AddSingleton(new LangfuseGenerationOptions
    {
        LinkPrompts = true, // Prompt name = command ID, version = revision.
        PricingScope = attempt => attempt.Snapshot.Registration.ClientRegistrationId == "claude"
            ? new PricingScope("anthropic-direct", "standard", "global")
            : null, // Unknown scope: no cost is sent.
    })
    .AddAttemptSink<LangfuseGenerationSink>();
```

`LinkPrompts` links a generation only to a Langfuse prompt that exists, so it stays off unless you manage prompts there. Pricing needs a scope that the host asserts: SKU, tier and geography are facts about your account, not about the response. Without a catalog or a scope, cost stays unknown, and Langfuse can infer its own. Only a complete USD estimate is sent. A partial one is omitted.

To emit from your own sink, call `LangfuseGeneration.EmitSafely` with the snapshot, `attempt.Correlation?.Parent ?? default`, `Started` and `Ended`. It isolates observation failures and never exports prompt or response text.

## Emit to a database

A database emitter is another `IAttemptSink`. It needs no Langfuse code, and the provider adapter does not know it exists. This sink writes one row per provider call through a host-owned store:

```csharp [AttemptRowSink.cs]
using System.Text.Json;
using System.Text.Json.Serialization;
using Zeeq.AgentCmd.Providers;

namespace QuickStart;

public sealed record AttemptRow(
    string AttemptId,
    Guid? ExecutionId,
    string Provider,
    string? Model,
    string End,
    DateTimeOffset Started,
    DateTimeOffset Ended,
    string UsageJson
);

// The application implements this over its own database.
public interface IAttemptStore
{
    ValueTask SaveAsync(AttemptRow row, CancellationToken cancellationToken);
}

public sealed class AttemptRowSink(IAttemptStore store) : IAttemptSink
{
    public ValueTask OnAttemptAsync(
        AttemptRecord attempt,
        CancellationToken cancellationToken
    )
    {
        var snapshot = attempt.Snapshot;

        // Preserve the usage evidence and keep unknown counts distinct from zero.
        return store.SaveAsync(
            new AttemptRow(
                snapshot.AttemptId,
                attempt.Correlation?.Command.ExecutionId,
                snapshot.Registration.ProviderKey,
                snapshot.ModelId,
                snapshot.End.ToString(),
                attempt.Started,
                attempt.Ended,
                JsonSerializer.Serialize(snapshot.Usage, AttemptRowJson.Default.UsageSnapshot)
            ),
            cancellationToken
        );
    }
}

[JsonSerializable(typeof(UsageSnapshot))]
internal partial class AttemptRowJson : JsonSerializerContext { }
```

Register it with `services.AddAttemptSink<AttemptRowSink>()`. Use `ProviderExtractionOptions.OnFailure` to report write failures. The middleware isolates sink failures so the model result can still return. To link rows to outputs, retain the execution ID and the exact output reference when the command returns `OutputDelivery.Stored`. To keep outputs and grades in a database, implement `IHumanFeedbackLedger`.

## Build a dataset from retained runs

Run dataset selection and grading separately from command execution. At capture time, retain searchable input records with their exact output references. Later, the reviewer searches the retained records and selects runs for a dataset. To grade a historical result, read that version from the ledger under an authorized actor. The [offline example](/examples/telemetry-and-evals) illustrates both stages with a local ledger and a deterministic grader.

Use the outcome's snapshot to inspect or deliberately retain the raw user template, rendered prompt and parameter records. `Outcome<T>.Success` also contains the validated value and a separate delivery receipt. For a leaf, `OutputDelivery.Stored.Output.Reference` identifies the exact stored provider JSON. A successful value with a rejected or failed delivery is not a stored evaluation artifact.

For a whole, use `CompositeOutcome<TWhole>.Published.Aggregate.Output`. Read that reference through the ledger under an authorized actor, then grade the whole or a JSON pointer within it. Component references remain useful for lineage; they do not replace the aggregate reference. The [composition example](/examples/composition) reads the stored whole and checks its grade and replay receipts.

For ordinary commands, `IEvaluationInputStore.SaveAsync` is the host-owned write boundary. Add a query to your store to find candidate records later, for example by command ID or run. Persist both the records and the output ledger when review may happen after a restart.

In the AgentCmd console, open a retained execution and use **Add to regression draft**. The control plane copies the retained input and asset references into the draft and keeps the original execution ID and any output reference as provenance. A reviewer supplies the reference answer separately. Reopen the resulting dataset from **Datasets** or fetch it through `GET /api/v1/datasets/{id}`. A benchmark uses the frozen dataset to replay its selected inputs. The host must report authorized input evidence to the control plane for production executions to be eligible for capture. See the [console walkthrough](/guides/management-console) and [management API reference](/reference/management-api).

For [runtime experiments](/guides/runtime-experiments), the ledger's evidence-aware write links the effective prompt, parameters, assignment and available attempt information to the exact output. A custom ledger must implement that write to store experiment outputs; the default interface rejects it rather than silently dropping the evidence. Telemetry remains a separate, best-effort observation.

Command traces include the selected experiment ID, revision, variant, role and fallback reason when available. A valid comparison-group identifier is also included, which lets a collector link primary and shadow traces. These tags do not include prompt or parameter values. Choose group identifiers that do not contain sensitive information.

A custom `IExecutionEventSink` can observe lifecycle events, but those events do not contain the full snapshot or output. It is best effort; it is not a durable journal. Replace `IHumanFeedbackLedger` and, for durable compositions, `ICompositionStore` with host implementations that enforce authorization, versioning and retention.

Treat prompts, parameters, output JSON and captured response text as potentially sensitive. Choose access, redaction and retention policies before storing or exporting them. Raw provider text is disabled by default; enabling `RawContentPolicy` captures bounded response items, not tool arguments. The built-in Langfuse generation adapter does not automatically send those contents.

## Usage, cost and limits

`PricingEstimator.Estimate(snapshot, scope)` combines observed usage with an explicit `PricingScope`, model binding and rate-card provenance. The estimate can be complete, partial or unpriced. Missing counts or prices are unknown, never zero. A token estimate is not invoice reconciliation.

The built-in rate cards are reviewed data. To apply a negotiated rate, price a private deployment or add a model this release does not know, build a catalog at setup and pass it to the estimator:

```csharp
var catalog = TokenPricingCatalog.Create(options => options
    .Override(negotiatedSonnetCard) // Replaces the built-in card it overlaps.
    .Add(privateDeploymentCard)); // Rejected if it overlaps an existing card.

var estimate = PricingEstimator.Estimate(snapshot, scope, catalog);
```

In a hosted app, register the same setup once with `services.AddAgentCmdPricing(options => ...)` and inject `TokenPricingCatalog`; call `catalog.Estimate(snapshot, scope)`. A second registration throws. `Remove(providerKey, modelId)` makes a model unpriced, and `Clear()` starts from an empty catalog. Give a custom card provenance that names the contract or source for its rates.

Native streaming accounting and OpenAI Responses extraction have explicit limits. The repository's local Langfuse test has sent and read back a generation from a self-hosted instance. Other collector profile tests verify OTLP requests against a local handler; they do not establish hosted-service readback. The package-only NativeAOT proof uses synthetic clients and does not establish NativeAOT support for every vendor SDK.
