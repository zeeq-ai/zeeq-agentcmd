To compare models, keep the task and input stable while recording which client and model produced each result. A profile names a route; it is not a new prompt definition. The runnable `examples/Zeeq.LlmCmd.CommandExample` uses two **synthetic** clients and makes no provider call.

## Register the routes

This excerpt uses the `client`, `reviewClient` and `actor` created by that example. `AddKeyedChatClient` registers host-owned MEAI pipelines; the LlmCmd registrations borrow them by key.

```csharp [Program.cs]
services.AddKeyedChatClient("openai", _ => client);
services.AddKeyedChatClient("claude", _ => reviewClient);

services.AddLlmCmd(options => options
    .AddChatClient("openai", fixedModel: "synthetic-model")
    .AddChatClient("claude")
    .AddProfile("extraction", "openai", "synthetic-model")
    .AddProfile("review", "claude", "synthetic-claude")
    .UseDefaultProfile("extraction")
    .UseActor(_ => actor)
).AddGeneratedCommands();
```

A fixed-model registration makes the binding explicit and must match the profile's model. A client declared without `fixedModel` can take the route's model per request. OpenAI Chat Completions SDK clients are model-bound, so use separate client registrations for distinct bindings. The Anthropic client can select its model per request. The names here are synthetic; they do not configure either vendor.

Client names are strings. In direct, statically understood setup, the shipped analyzer reports unknown client names (`LLMCLIENT001`), duplicate client names (`LLMCLIENT002`) and fixed-model conflicts (`LLMCLIENT003`). Dynamic or otherwise unsupported setup remains subject to runtime validation. See [Diagnostics and limits](/reference/diagnostics-and-limits).

## Execute independent trials

Once the host has resolved `ExtractInvoice` and `IHumanFeedbackLedger`, the same command can run under either route:

```csharp [Separate trials]
var firstRun = ledger.CreateRun(actor);
var secondRun = ledger.CreateRun(actor);
var input = new InvoiceParameters("Invoice for USD 12.50");

var first = await extract.WithParameters(input)
    .WithProfile("extraction")
    .InRun(firstRun)
    .ExecuteAsync();
var second = await extract.WithParameters(input)
    .WithProfile("review")
    .InRun(secondRun)
    .ExecuteAsync();
```

Check each `Outcome<Invoice>` and its delivery before comparing values. A success snapshot records the selected profile and model; attempt capture can carry additional routing evidence. Separate runs are one way to keep trial identities distinct. For composed trials, also use distinct trial or draft identities: changing a route does not make it safe to reuse an immutable composition key.

::tip
A generated profile catalog can give `WithProfile` typed keys. It declares profile IDs; the host still registers and validates their routes.
::
