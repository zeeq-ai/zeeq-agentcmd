# Quality floor

The .NET SDK supplies the analyzers; no third-party analyzer package is required. Root build properties enable nullable analysis and warnings as errors, including exhaustive-match compiler errors CS8509 and CS8524. `src/Directory.Build.props` enables XML documentation and makes CS1591 and incomplete parameter comments fail production builds. Tests, fixtures and examples need not document their public members. Generated source suppresses CS1591 in the generated file itself, without marking an author-owned partial type as generated.

A focused analyzer set in `.editorconfig` covers ValueTask consumption (CA2012), cancellation forwarding (CA2016), stack-preserving rethrows (CA2200), argument-exception parameter names (CA2208), structured logging template counts (CA2017), broken cryptography (CA5351), and obsolete TLS versions (CA5364). Each rule is a warning; warnings-as-errors makes violations fail the build. Production projects use analysis level 11.0 and the SDK default analysis mode rather than every rule. SDK analyzers are enabled explicitly for the netstandard generator too. Generated-code detection suppresses analyzer diagnostics, but not compiler diagnostics.

Braces are the one build-enforced style rule (IDE0011), across maintained C# source. A later edit must not leave a statement outside its intended conditional or loop. `mise run format` applies the SDK brace fix before CSharpier, then checks the exact preview-syntax files with the SDK formatter. The build rejects missing braces; no broad style rule set is enabled. Formatter edits move caller source lines, so tests must check the application call site without hard-coding a formatter-dependent line offset.

The package-consumer test verifies both sides of the documentation boundary: an undocumented authored command fails with CS1591, while a documented command and generated typed profile catalog build successfully with documentation and warnings-as-errors enabled. XML files ship beside the library assemblies for callers' IntelliSense.

The core package also includes three [client-registration diagnostics](client-registration-analysis.md). They reject proven unknown clients, duplicate client IDs and constant fixed-model conflicts in supported local setup. They share the generator assembly rather than add another analyzer dependency. Dynamic setup retains runtime validation. Offline semantic tests and the NuGet-only consumer check both errors and conservative handling of unknown inputs.

In an isolated .NET 11 RC probe, the selected set found one cancellation-forwarding issue and no other violations. Opting into CA2000 produced three ownership findings that need human review; returning a disposable to a caller can be intentional. The probe found 816 missing public documentation locations across the three library projects, four in the generator, and 19 incomplete parameter documentation locations. These counts measure warning locations rather than documentation quality.

References: [Microsoft analyzer configuration](https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/configuration-options), [XML documentation](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/xmldoc/), and [CS1591](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/compiler-messages/cs1591).
