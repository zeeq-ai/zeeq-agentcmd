# Provider pricing

The estimator uses a static first-party rate card retrieved 2026-11-02, in USD per million tokens. This is an estimate, not an invoice; taxes and negotiated pricing are excluded. The caller must assert the actual SKU, service tier and geography. Unknown scope is not standard by default.

`PricingEstimator` is a facade over the immutable `TokenPricingCatalog.Default`. Hosts can supply another catalog. Protocol partition rules are shared across model cards; there is no Haiku or Luna estimator subclass. Exact platform, model version, SKU, tier, geography, pricing date and context band select a card. Cards may cover disjoint date intervals or context bands; overlapping matches are rejected. The estimate retains the selected card revision and band.

For the direct Claude API, `claude-haiku-5-5`, standard service and global routing, [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing) lists $0.10 input, $0.01 cache read, $0.125 five-minute write, $0.20 one-hour write and $0.50 output through 100,000 inclusive prompt tokens. Above that threshold the rates are $0.50, $0.05, $0.625, $1 and $2.50 respectively. The prompt includes cache reads and writes. The card's effective date was not stated. Batch and US-only inference have different prices and are not supported.

The same source lists Sonnet 5.5 at $2 input, $0.10 cache read, $2.50 five-minute write, $4 one-hour write and $10 output. Opus 5.5 is $4, $0.20, $5, $8 and $20 respectively. Both use standard rates across their full 1M context window; they do not inherit Haiku's threshold. All three cards share Messages input and TTL partition validation.

For Azure OpenAI `gpt-6-luna` and the documented version `gpt-6-luna-2026-09-22` ([Microsoft model listing](https://learn.microsoft.com/en-us/azure/foundry/foundry-models/concepts/models-sold-directly-by-azure)), the [Microsoft announcement](https://azure.microsoft.com/en-us/blog/gpt-6-astra-sol-and-luna-for-production-agents-in-microsoft-foundry/) lists Global Standard rates in USD per million tokens. Short context: input $0.10, cache read $0.01, cache write $0.125, output $0.50. Long context: $0.20, $0.02, $0.25 and $0.75 respectively. The announcement does not specify the context threshold; the caller must explicitly supply `short` or `long` after independently establishing the applicable band. This is an assumption attached to the estimate, not a verified threshold. The effective date of the rate card is unstated. The dynamic [Azure pricing page](https://azure.microsoft.com/en-us/pricing/details/azure-openai/) does not expose numeric prices in the retrieved content. Data Zone, priority, provisioned and other SKUs are unsupported. Input, cache read and cache write must all be observed to calculate input cost; absent counts are unknown.

That Azure announcement also lists GPT-6 Sol short rates of $2 input, $0.20 cache read, $2.50 cache write and $10 output; long rates are $4, $0.40, $5 and $15. Astra short rates are $10, $1, $12.50 and $50; long rates are $20, $2, $25 and $75. Their context bands remain caller-asserted.

The [Azure GPT-5.6 announcement](https://azure.microsoft.com/en-us/blog/gpt-5-6-now-available-in-microsoft-foundry/) lists Terra short-context rates of $2 input, $0.20 cache read, $2.50 cache write and $12 output. Sol's published short-context cache prices are $0.50 read and $6.25 write; its promotional input/output prices are $4/$20 from September 1 through at least November 30, 2026. The conservative built-in Sol card requires `PricingScope.AsOf` within that reviewed interval. Replays use the stored request date, not today's date. No long-context 5.6 rate is extrapolated from a different platform. Numeric Azure GPT-6.1 Sol prices were not available in the retrieved first-party content, so that model remains unpriced.

The same `ModelTargetBinding` is used for request validation and `PricingScope.TargetBinding`. A captured Azure target must agree with that binding and the reported version. A missing binding for a captured target is unpriced. Legacy snapshots without `RequestedModelId` can price the reported model only; the estimate states that deployment drift was not checked. No arbitrary version suffix inherits a known model price.

Only token charges are estimated. Unknown, inconsistent, incomplete or separately chargeable usage prevents a complete total. Missing counts are not assumed to be zero. KnownUsd is a partial token estimate, not a lower bound on an invoice after discounts.

The sanitized live replay contains an unknown `$.usage.latency_checkpoint` object. Its name suggests latency metadata, but its contents were not retained, so this cannot establish whether it has billing relevance. The estimate covers the observed token counters only.

Observed billing metadata must agree with the selected rate card. Anthropic requires standard service, global geography and standard speed; Azure accepts default or standard service, global geography and standard speed. A nonstandard or unknown observed value is unpriced. When metadata is absent, the estimate states that the caller supplied the missing scope as an assertion. Standard speed is part of that assertion.
